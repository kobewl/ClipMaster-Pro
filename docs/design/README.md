# ClipMaster Pro · UI 设计规范

> 版本 1.0 · 2026-09-17 · 对应产品版本 0.01 Beta
> 窗口尺寸 800 × 600 · 平台 macOS 13+

这份文档是 ClipMaster Pro 界面设计的唯一依据。原型图在 `prototype/prototype.html`，
逐屏截图在 `prototype/shots/`，机器可读的色值在 `tokens.json`，Logo 源文件在 `logo/`。
**在线可编辑版在腾讯 Ardot**（见第八节）。

---

## 一、设计原则

**1. 应用，不是网页。**
界面直接铺满窗口，不做「窗口里飘一张圆角卡片」的包装。macOS 原生应用（备忘录、提醒事项）
都是内容面顶到边缘；套壳式包装会让人觉得这是个被塞进窗口的网页，还白白吃掉一圈可用面积。

**2. 一屏之内做完所有事。**
这是一个用全局快捷键唤起、选一条、立刻消失的工具。用户不会在这里停留，所以：
不引入侧边栏、不做多级导航、任何操作最多一次点击。

**3. 让内容当主角。**
用户来看的是自己复制过什么。装饰元素（阴影、渐变、色块）一律退到背景里，
不为「好看」牺牲一行的信息密度。

**4. 颜色只说一件事。**
一个强调色（Iris 靛蓝）贯穿全局，用来标记「当前选中 / 主要操作」。
成功、警告、危险是状态色，不参与品牌表达。

## 二、颜色

### 2.1 品牌色 Iris

整个界面唯一的强调色。它的职责是回答「我现在选中了哪个 / 该点哪个」。

| 令牌 | 色值 | 用途 |
|---|---|---|
| `iris.500` | `#5B5FEF` | 主色：主按钮底、选中色条、品牌底 |
| `iris.600` | `#4A4EDD` | 悬停态 |
| `iris.700` | `#3C3FBE` | 按下态 |
| `iris.100` | `#E8E9FF` | 浅色模式下的淡底 |

Logo 底色额外使用 `#6E6BF7 → #4B4EE6` 的 45° 渐变，比纯色更有体积感。

> 对比度：`#5B5FEF` 上的白字对比度为 5.9:1，达到 WCAG AA。
> 强调色当**文字**用时改为 `accentText`（浅色 `#4448D6`，深色 `#A5A7FA`），
> 因为 `iris.500` 直接做文字对比度只有 4.2:1，中文字号小的时候会吃力。

### 2.2 语义色（浅色 / 深色）

组件里**只允许**使用这一层，不允许出现任何硬编码色值。

| 语义 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `bg` | `#F2F3F7` | `#08090D` | 窗口最底层 |
| `surface` | `#FFFFFF` | `#121419` | 主内容面 |
| `surface2` | `#F6F7FA` | `#191C23` | 次级面：搜索框、内嵌区块、状态栏 |
| `surface3` | `#FFFFFF` | `#1E2229` | 浮层：菜单、弹窗 |
| `line` | `rgba(17,20,45,.08)` | `rgba(255,255,255,.085)` | 分隔线、控件描边 |
| `lineStrong` | `rgba(17,20,45,.15)` | `rgba(255,255,255,.17)` | 悬停描边、虚线框 |
| `hover` | `rgba(17,20,45,.045)` | `rgba(255,255,255,.055)` | 悬停底、骨架屏底色 |
| `fg` | `#14161F` | `#ECEEF4` | 正文 |
| `fgMuted` | `#5A5F72` | `#9EA3B6` | 次要文字、标签 |
| `fgFaint` | `#8A8FA3` | `#6C7186` | 时间戳、占位符、辅助说明 |
| `accent` | `#5B5FEF` | `#7B7EF5` | 强调色 |
| `accentSoft` | `#EEEEFF` | `rgba(107,110,245,.16)` | 选中底、图标底 |
| `accentRing` | `rgba(91,95,239,.30)` | `rgba(123,126,245,.38)` | 聚焦描边 |
| `success` | `#0FA47F` | `#34D3A6` | 采集中状态点 |
| `danger` | `#E5484D` | `#F87171` | 危险操作 |
| `highlight` | `#FFE9A8` | `rgba(250,204,21,.26)` | 搜索命中 |

**深色模式不是简单反色**：把浅色的 `#FFFFFF` 直接翻成 `#000000` 会刺眼。
这里的深色面用 `#121419`（带一点蓝的深灰），并且**深色下所有颜色对比度都调低一档**，
避免在暗环境里发光。

## 三、字体

**字体栈**：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Helvetica Neue", Arial`

macOS 上会落到 SF Pro Text + 苹方，中英混排的字重和基线最协调。

### 3.1 字阶

只有 4 档。**不要再加档位**——字阶一多，界面的层级感就散了。

| 令牌 | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `caption` | 11.5px | 16px | 400–650 | 时间戳、来源名、状态栏、辅助说明 |
| `label` | 12px | 17px | 500–600 | 分组标签、按钮文字、菜单项 |
| `body` | 13px | 19px | 400 | **历史记录正文**、输入框 |
| `title` | 14.5px | 21px | 650 | 应用名、弹窗标题 |

字重只用 400 / 500 / 600 / 650 / 700 五档。**中文不要用 700 以上**，
苹方在重字重下会糊；需要强调时优先加大字号或换颜色。

### 3.2 字距

- 正文与界面文字：`-0.003em`（轻微收紧，中文更整齐）
- 标题类：`-0.014em ~ -0.025em`（字号越大越收紧）
- 全大写标签（PRO、分组标题）：`+0.02em ~ +0.06em`（小字距放开才好读）

## 四、间距与尺寸

### 4.1 间距阶

`2 / 4 / 6 / 8 / 10 / 12 / 14 / 18 / 24 px`。所有间距必须是其中某一个。

### 4.2 关键尺寸

| 元素 | 尺寸 |
|---|---|
| 窗口 | 800 × 600（可调整） |
| 顶部栏高 | 52px（含 11px 上下内边距） |
| 搜索框高 | 32px |
| 分组标签高 | 26px |
| 历史行距 | 单行约 54px，双行约 73px |
| 来源图标 | 30 × 30px |
| 状态栏高 | 32px |
| 悬停操作条 | 25px 按钮 + 2px 内边距 |
| 弹窗宽 | 设置 430px / 分组管理 430px / 确认 336px |

### 4.3 圆角

| 令牌 | 值 | 用途 |
|---|---|---|
| `xs` | 5px | 快捷键键帽、分组徽标 |
| `sm` | 7px | 按钮、输入框、分组标签 |
| `md` | 9px | 搜索框、来源图标、图标按钮 |
| `lg` | 12px | **历史记录行**、内嵌区块 |
| `xl` | 14px | 弹窗、空状态图标 |
| `pill` | 999px | 状态点、色板圆点、提示条 |

> 历史记录行用 12px 而不是更大：行高只有 54px 左右，圆角超过 14px 会显得「软」，
> 失去工具的利落感。

### 4.4 阴影

四档，以「离页面多远」命名。**阴影只用于真的要浮起来的元素**（菜单、弹窗），
普通区块用 1px 描边分隔，不要用阴影。

| 令牌 | 用途 |
|---|---|
| `sh1` | 键帽、极轻的分离感 |
| `sh2` | 悬停操作条 |
| `sh3` | 菜单、弹窗 |
| `shWindow` | 仅原型画板的窗口外框，产品内不用 |

## 五、组件

### 5.1 顶部栏

```
[Logo 26px] ClipMaster [PRO]  |  搜索框（自适应）  |  [设置 32px]
```

- 整条都是拖拽区（`data-tauri-drag-region`）；**注意**：Set 按钮与搜索框要排除在外，
  否则点不动。
- `PRO` 角标：9.5px / 700 / `+0.06em`，`accentSoft` 底 + `accentText` 字。
- 搜索框：左内边距 33px 给放大镜图标，右内边距 62px 给快捷键提示。
- **快捷键提示只在没输入内容时显示**，一旦开始输入就换成「清空」按钮——
  两者都占右侧空间，同时出现会挤。

### 5.2 分组筛选条

```
[全部 30] [● 工作 8] [● 设计 5] [● 链接 3]        [+ 分组]
```

- **「管理」按钮固定在右侧，不参与横向滚动。** 原实现把它放在滚动容器里，
  分组一多就被滚出视野，用户找不到入口。
- 分组标签：26px 高，色点 6px，计数用 `tabular-nums` 对齐。
- 选中态：`accentSoft` 底 + `accentRing` 内描边 + `accentText` 字。
- 滚动区做了右侧渐隐遮罩，暗示「还有更多」。
- **不设「视图」标签**——它占 24px 宽却零信息量，「全部」本身就是最好的说明。

### 5.3 历史记录行

```
[图标]  来源 · 时间 · [分组徽标]
        正文（最多两行，超出省略）
```

- 图标 30×30px：图片类型用图片图标，文本类型用来源 App 的 emoji。
- 来源名用 `fgMuted` + 600 字重；时间与分隔点用 `fgFaint`，视觉上退后一层。
- 分组徽标：11px 文字，底色为分组色的 12% 透明度，文字用分组色本身。
- **正文右侧留 58px 空白**，给悬停操作条让位。宁可留白，也不让文字钻到按钮底下。
- 一行最多两条正文（`-webkit-line-clamp: 2`），保证一屏能看到 8–10 条。

**三种状态**（互斥，不要混用）：

| 状态 | 触发 | 表现 |
|---|---|---|
| 键盘选中 | ↑↓ 移动 | `accentSoft` 底 + `accentRing` 内描边 + 左侧 2.5×21px 色条 + 右下「↵ 粘贴」 |
| 鼠标悬停 | hover | `hover` 底 + 浮出操作条 |
| 菜单展开 | 点文件夹图标 | 保持选中样式 + 操作条常驻 + 文件夹按钮高亮 |

> 选中态**不用**「3px 内阴影色条 + 斜向渐变」：渐变在深色模式下几乎不可见，
> 而独立的圆角色条两种模式都成立，也不会被 `inset` 阴影的直角切掉。

### 5.4 悬停操作条

两个按钮（分组 / 删除）包在**一个整体容器**里，带 `surface` 实底 + 1px 描边 + `sh2`。

原实现是两个各自带独立投影的圆钮，压在文字上会糊成一片；
整体化之后既清晰又像一个控件组。

- 未悬停时 `opacity: 0` + `pointer-events: none`，避免误触看不见的按钮。
- 菜单展开时必须强制可见（父级 `opacity` 会作用到菜单子树）。
- `focus-within` 时同样可见，保证键盘 Tab 能操作。

### 5.5 状态栏

```
● 正在采集 | 共 30 条 · 已显示 8              ↑↓ 选择 ↵ 粘贴   清空未分组
```

- 采集状态：绿点（带 3px 光晕）+ 绿色文字 `正在采集`；暂停时点变灰、文字变 `fgMuted`。
  **不用红色**——暂停是正常状态，不是错误。
- 键盘提示只在屏幕够宽（≥620px）时显示。
- 「清空未分组」默认 `fgFaint`，悬停才变危险色：它是低频操作，不该一直抢注意力。

### 5.6 弹窗

- 遮罩：`overlay` + `backdrop-filter: blur(9px) saturate(.92)`。
- 卡片：`surface3` + 1px 描边 + `sh3`，圆角 14px。
- 头部：34px 圆角图标底 + 标题 + 副标题，右侧关闭按钮。
- 内嵌区块（数据保留 / 全局快捷键）：`surface2` 底 + 1px 描边 + 10px 圆角。
- 按钮：主按钮 `accent` 底白字；次按钮 `surface` 底 + 描边。
- 危险确认弹窗（清空历史）用居中布局 + 40px 红色图标，按钮居中。

### 5.7 空状态与加载

- 空态：46px 圆角图标底（`accentSoft` + `accentRing`）+ 主文案 + 一句辅助说明。
  文案随场景变化：「开始收集你的剪贴板」/「没有找到匹配的记录」/「加载失败」。
- 骨架屏：7 行，模拟真实的「图标 + 两行文字」结构，宽度带随机抖动。
  比一句「加载中」更接近最终布局，视觉上不跳。
- 加载中的 shimmer 在深色模式下**必须调低亮度**（`rgba(255,255,255,.09)`），
  否则会在暗背景上闪光。

## 六、动效

只有一条曲线：`cubic-bezier(0.32, 0.72, 0, 1)`（快出慢入，macOS 的标准手感）。

| 场景 | 时长 | 效果 |
|---|---|---|
| 悬停变色 | 110ms | 背景 / 文字色 |
| 菜单出现 | 110ms | `translateY(-3px) scale(.97)` → 原位 |
| 弹窗出现 | 240ms | `translateY(6px) scale(.976)` → 原位 |
| 遮罩 | 160ms | 淡入 |

所有动效在 `prefers-reduced-motion: reduce` 下关闭。

## 七、Logo

**定稿**：剪贴板剪影 + 三条内容线 + 完整材质。

### 构成

| 部件 | 规格 |
|---|---|
| 底板 | 512×512，圆角 116，45° 渐变 `#7C79FF → #5B5FEF → #4346D6` |
| 底板柔光 | 左上角径向渐变，`#B4B2FF` 从 62% 透明衰减到 0（半径 0.82） |
| 边缘高光 | 1.25px 内描边，白色 20% 透明 |
| 纸张 | `x124 y112 w264 h288 rx58`，自上而下 `#FFFFFF → #FCFCFF → #EDEEFB` |
| 纸张投影 | `feDropShadow dy=12 stdDeviation=15`，`#141645` 30% |
| **夹子** | `x204 y84 w104 h58 rx29`，**深靛蓝渐变 `#4B4EE4 → #2F32A8`** + 白色 22% 描边 |
| 内容线 ×3 | `h34 rx17`，宽 160 / 124 / 146，不透明度 100% / 55% / 26%，亮渐变 `#6D6AFA → #4B4EE4` |

### 为什么是这个形状

四轮探索后的结论：

1. **剪贴板剪影在任意尺寸下都最清晰。** 越抽象的方案（C 形分段环、纯叠卡）
   在小尺寸下越容易和其他图标撞脸——两个偏移的圆角方块在 32px 会读成同心边框。
2. **三条线递弱形成节奏**，一眼看出是「一列记录」。两条线更像「一张纸」，信息量偏弱。
3. **≤24px 切换剪影版**：只留外轮廓和夹子。内容线在这个尺度下会并拢成一坨灰。

### 「好看」来自哪里

这一点值得单独说明，因为它决定了这个 Logo 能不能被正确复用：

**好看主要来自材质，不是来自形状。** 形状部分（一个白块 + 三条线）本身很朴素；
真正让它显得现代的是四处细节：

- 底板左上的柔光，让整块渐变有了「光源方向」，而不是均匀的色块
- 1.25px 的边缘高光，模拟真实材质的倒角
- 纸张向下的柔和投影，让它**浮**在底板上而不是平贴
- **夹子比内容线更深一档**——夹子位于图标顶部，而那里恰好是底板渐变最亮的位置，
  两者同色系时会在 32px 以下糊在一起。加深后夹子才能「立」住

所以：**任何试图「简化」这个 Logo 的做法，都应该先砍形状（内容线），最后才考虑砍光影。**
剪影版就是照这个原则做的——它去掉了内容线，但完整保留了柔光、投影、纸张渐层和加深的夹子，
因为在托盘里的小图标不应该比 Dock 里的大图标显得廉价，它们是同一个东西。

### 交付文件

| 文件 | 用途 |
|---|---|
| `logo/clipmaster-logo.svg` | 主 Logo，≥22px 使用（依赖 SVG filter） |
| `logo/clipmaster-logo-small.svg` | 剪影版，≤24px 使用（菜单栏、托盘） |
| `logo/clipmaster-logo-flat.svg` | 平面降级版，给不支持 filter 的渲染器兜底 |
| `logo/clipmaster-logo-mono.svg` | 单色版，用 `currentColor` |
| `logo/clipmaster-icon-1024.png` | 应用图标源图，透明背景，供 `tauri icon` 生成全套 |
| `logo/clipmaster-icon-small-512.png` | 剪影版源图 |
| `logo/clipmaster-icon-flat-512.png` | 平面版源图 |

生成应用图标：

```bash
npx tauri icon docs/design/logo/clipmaster-icon-1024.png
```

### 使用禁忌

- 不要拉伸变形（底板圆角比例是设计的核心，等比缩放才成立）
- 不要换底色（品牌渐变是识别度的一部分）
- 不要让底板圆角小于 22%（会变成方块，失去应用图标感）
- 不要把光影压平（见上文「好看来自哪里」）

颜色照本文档第二节的语义令牌改。画布上的色值已经按令牌刷过一遍，
改一处颜色时建议全局替换，不要单点改，否则会出现「一半新一半旧」。

Ardot 里的画板顺序和 `prototype/shots/` 的截图编号完全一致（01–13）。
